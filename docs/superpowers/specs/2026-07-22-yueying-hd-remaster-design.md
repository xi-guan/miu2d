# 月影传说高清重制 — 设计

日期: 2026-07-22
范围: yueying (sword1 / sword2 不在本轮)

## 目标

保留游戏本体 —— 玩法、手感、平衡、引擎坐标系全不动,只提升画质。

明确**不做**真重制: 不重做游戏内角色 sprite,不碰 8 方向 × 多帧的一致性问题。

## 已验证的实验结论

2026-07-22 用 3 类真实素材 × 5 种放大方式做了 1:1 对照,产物页:
https://claude.ai/code/artifact/d83974ca-13a4-4c71-8b95-e83b753df483

```
立绘 200×160   AI 超分脱胎换骨, 眼睛发丝干净        → 值得做, 生成式重绘上限更高
角色  83×89    3 个 AI 模型全部把面部抹平            → 不用 AI, 只做 nearest 放大
物件 512×468   栏杆边缘略好, 整体更糊(低对比水雾)   → 逐个判断, 高对比的才做
```

核心结论: **决定成败的是源素材分辨率,不是模型**。同一个 x4plus-anime 在立绘上是赢家,
在角色 sprite 上是灾难。三个 AI 模型之间的差异,远小于三类素材之间的差异。

反直觉的一条: nearest(完全不用 AI)在角色 sprite 上**赢过**三个 AI 模型 —— 它保住了五官轮廓。

## 素材规模

```
portrait   109   立绘
object     192   场景物件
ui          67   UI 素材(按功能分子目录)
character 2086   不生成新素材
```

实际要产出新素材的只有 368 个文件。

## 架构: hd/ 旁路覆盖层

```
resources/yueying/asf/…      原素材, 不动
resources/yueying/hd/…webp   新素材, 按原文件名映射
```

引擎加载时先查 `hd/`,命中就用,否则回退原 asf。原素材、wasm 解码器、MSF 容器格式
全部不动。带开关,可随时原版/高清对比,失败就删 `hd/` 目录干净回退。

选这条而不是"写回 ASF 容器",是因为 ASF 是 256 色调色板格式 —— 重绘出的真彩色压回去,
补的细节正好死在调色板量化上,等于白做。

## 四条素材线

```
立绘   生成式重绘。保结构编辑模型(Flux Kontext 类)优于普通 img2img,
       因为要锁住原构图。单帧、无跨帧一致性问题,风险最低。
物件   先跑超分, 按纹理对比度分流: 建筑/岩石/树等高对比的做,
       水雾/烟/光效等低对比的跳过(已验证收益差)。
UI     生成式重绘 + 逐个人工校对。按钮边框这类几何图形 AI 容易画歪、
       画出不对称,必须看过才放行,不能批量通过。
sprite nearest 放大, 渲染时处理, 不产出新素材文件。
```

## 引擎改动

- `resource-loader` 加一层 hd 查找与回退
- 角色绘制的 scale 与锚点,仅在启用 hd 时生效
- **不动** `map-renderer.ts` 的 64×32 tile 坐标系

## 明确不做

- 8 方向 sprite 的跨帧一致性(2026 年初仍是公开未解问题)
- image-to-3D 重建管线
- mpc 地图 tile 与 tile 坐标系改动
- sword1 / sword2

## 风险

- **角色特征漂移**: 生成式重绘会改变脸和服饰细节。109 张立绘必须人工筛选,不能全自动。
- **风格割裂**: 立绘变精美而游戏内 sprite 仍是像素块,可能比全糊更难看。这一条只能在游戏内
  实际观感验证,做完立绘先看效果再决定是否继续。
- **体积**: hd 素材使内容镜像变大,影响 `just release game-<slug>` 的分发。

## 验证方式

每条线做完先在游戏内看实际观感,由用户确认,再决定是否推进下一条。不一次铺开四条线。

临时性质。若不进入正式实现可删除。

## 术语

本文档统一用 **sprite** 指代"独立于背景、能单独移动的图块"(即角色在地图上走动时逐帧
播放的那些图)。不使用中文直译"精灵" —— 该译名丢失了原意,易与奇幻生物混淆。
